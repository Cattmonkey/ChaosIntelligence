# Web 色彩设计与维护

0.62.1 的 Web 界面以 Johannes Itten 的色彩对比理论为设计参考，统一 IDE、图形编程、系统控制台、在线与离线文档的配色。这里的数字色值和语义角色是本系统的设计选择，并非 Itten 规定的界面色值或固定面积比例。

## 理论如何用于编程环境

| 对比原则 | 本系统的应用 |
|---|---|
| 明暗对比 | 工作区、面板与浮层逐层变亮；正文、辅助文字、代码注释保持足够的明度差 |
| 冷暖对比 | 低饱和冷蓝灰覆盖主要工作区，暖琥珀突出主要操作，蓝色与选中底色标识当前位置 |
| 互补对比 | 以蓝与橙的艺术配色关系组织冷背景与暖强调，不把传统颜料色轮直接当作 RGB 混色公式 |
| 纯度对比 | 大面积背景降低饱和度，角色、状态和必要交互用较清晰的颜色 |
| 面积对比 | 明亮强调集中在按钮、焦点和小型标记；连续阅读区域保持安静，不规定机械的百分比 |

这些原则提供视觉层级，具体可读性通过浏览器计算后的颜色测量。半透明层需与实际背景合成，不能只比较原始十六进制值。

## 色彩承担的含义

| 内容 | 颜色方向 | 其他识别线索 |
|---|---|---|
| 主要操作 | 琥珀 | 按钮文字与操作位置 |
| 当前入口、键盘焦点 | 蓝 | 选中底色、位置与焦点轮廓 |
| 智能体与平台角色 | 紫罗兰 | 节点类型、名称与层级关系 |
| 普通函数 | 蓝 | 函数类型与源码签名 |
| 工具 | 琥珀 | 工具类型、参数与能力说明 |
| 成功、完成、就绪 | 薄荷绿 | 状态文字与执行信息 |
| 错误、失败 | 珊瑚红 | 错误文字与失败状态 |
| 辅助说明、注释 | 浅蓝灰 | 所在位置与文字内容 |

主要操作与工具可以采用相近暖色，但成功状态独立使用绿色。状态仍由文字、图形和执行数据表达，颜色不能成为唯一信息来源。

## 单一主题与维护方式

主题入口是 `web/theme.css`。页面 CSS 和 CodeMirror 编辑器通过语义变量引用颜色，不在各个页面重复定义新的色值。新增按钮、节点、状态和代码类型时先选择合适的语义变量；确需新的角色颜色时，在主题文件中定义并检查其相邻背景上的对比度。

IDE、控制台和文档页面共同加载主题。共享代码阅读组件自身加载主题，因此独立嵌入的阅读器与 IDE 使用相同的语法色彩。服务同时提供 `/theme.css` 和 `/docs/theme.css`；文档导出将主题复制到离线站点，不依赖远程主题服务。

打印通过独立媒体规则切换到浅色纸面与深色文字，语法颜色也需要在白纸上保持可读。主题调整保持原有语言语法、项目格式、调用接口、编辑器操作和用户配置。

## 验证范围

按照 W3C 的对比度定义，普通文字以 4.5:1 为检查门槛，大文字和必要非文字图形以 3:1 为门槛。禁用元素和装饰边界需单独区分；不能用这些例外豁免正在使用的文字与控件。验证应覆盖正文、辅助文字、语法注释、选中行、悬停、运行与失败状态、键盘焦点，以及半透明思考区域。

本次保留浏览器实际颜色与合成背景的抽样测量、桌面与移动界面截图、代码编辑和运行回归、离线文档与打印检查。这些检查支持本次配色的可读性结论，不代表整个系统获得 WCAG 合规认证。
