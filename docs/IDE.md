# IDE 与智能体编程

Chaos 默认打开源码工作台：左侧活动栏与文件列表、中间编辑器、底部可展开的运行输出。编程助手、调试、图形工具和运行输入按需打开，编辑器使用随安装包提供的 CodeMirror，无需外部 CDN。源码、程序结构、SDK 和运行按钮仍操作同一项目及版本。

目录项目的运行按钮执行默认入口，选中文件只切换编辑对象。入口同时由项目标记和 IDE 持久项目记录；已有项目需要切换入口时按[用户指南](USER_GUIDE.md)协调两侧，不能只修改标记文件后重启。

## 打开自己的项目

完整项目目录中先执行 `python3 chaos.py setup`（首次显式安装完整依赖），再执行 `python3 chaos.py`。以终端报告的实际URL为准，端口默认由系统选择；需要无浏览器启动可用 `python3 chaos.py ide --no-browser`。源码留在项目目录，IDE状态在 `.chaos/project.sqlite3`；同目录 CLI 默认 run 的内存历史与它不同。

从[快速开始](GETTING_STARTED.md)完成第一个程序，再用本页学习保存、调试和跨文件导航。编程助手的连接、角色与密钥来源见[模型配置](MODEL_CONFIGURATION.md)；打开助手或选择代码不会自动发送模型请求。

## 工作台导航

先在文件列表选择模块，编辑、格式化并保存，再运行入口程序。顶部保留保存、运行和运行时的停止按钮；其下的“文件、编辑、视图、运行、智能体、帮助”菜单按用途组织功能。当前文件标签旁可直接点击“格式化”“检查”“与助手编程”；“与助手编程”打开并聚焦现有对话，不发送请求。底部显示连接、版本和同步状态。在同一编辑视图内，文件侧栏、输出和助手等显示面板的开关只改变界面，不保存草稿、不提交项目版本，也不执行语言代码。从源码切换到程序结构或关系画布时，仍沿用原有的必要保存、语法校验和版本冲突规则。

不记快捷键也能完成首次编程：在文件列表选择已有入口 `main.chaos`，编辑并保存；在“运行 → 输入与调试设置”确认入口路径与输入，点击顶部“运行”，底部自动显示结果。更多模块通过“文件 → 新建模块”创建并从入口导入。运行执行整个程序的入口，当前打开的文件不一定是入口，文件树会标记入口模块。目录项目要更换入口时，按[用户指南](USER_GUIDE.md)协调已保存项目与 `chaos.project.json` 并重启。

菜单与命令面板使用同一命令和原有控件。菜单支持方向键切换和选择、Enter 执行、Escape 关闭并回到菜单按钮；F10 聚焦菜单栏。保存时格式化和运行追踪的勾选反映实际设置，不另存一份状态。

`Ctrl/Cmd-Shift-P` 打开命令面板，可搜索功能并用上下方向键、Enter 选择；Escape 关闭并回到此前焦点。`Ctrl/Cmd-P` 快速打开项目文件，`Ctrl/Cmd-B` 切换文件侧栏。命令面板使用明确登记的功能名称，不解析自然语言来猜执行操作。

| 任务 | 入口 |
|---|---|
| 文件、新建模块、打开文件 | 文件菜单、活动栏文件入口、文件列表或快速打开 |
| 查找、格式化、参数提示、引用与重命名 | 编辑菜单；格式化和检查也在文件标签旁 |
| 输入、JSON解析、运行选项 | “运行 → 输入与调试设置”或活动栏“调试”；显示实际入口文件 |
| 向正在执行的程序追加指导 | 命令面板“运行：追加当前运行指导”；程序需主动接收 |
| 编程对话 | 编程助手入口；默认关闭，打开不会自动发送请求 |
| 调试、断点与任务状态 | 运行菜单中的调试器及原调试面板 |
| 关系画布、程序结构、结构验证 | 视图菜单；原源码／IR同步规则不变 |
| Team、Program候选、Process、AgentSession、Computer | 智能体菜单；进入原有编辑器和管理面板 |
| 输出、页面报告、历史与执行快照 | 底部输出及命令面板；正在运行的版本仍明确显示 |
| 文档、系统配置与后台任务 | 活动栏或命令面板中的明确入口 |

“视图 → 恢复默认布局”重新显示文件侧栏并收起助手、输出和辅助面板，保留当前语义视图、源码及未发送的对话；小屏回到编辑器，文件列表按需以浮层展开。文件、输出等显示偏好可保存在当前浏览器；存储被禁用或格式无效时采用安全默认值。偏好不包含源码、密钥、运行输入或项目授权。版本冲突提示、草稿备份和载入远端操作仍保持可达，面板收起不会把有冲突的草稿当成已保存。


## 项目权限

从“文件 → 项目权限”或命令面板打开项目授权。选择只加入项目草稿，随后通过原保存或运行流程，与当前源码／结构 IR 在同一版本检查中提交。打开对话框、查看已注册设备或选择 Agent 工具不会自动授权；快照只读。远端版本冲突和保存期间的新输入保持草稿，按原冲突流程处理。

“可调用工具”用于模型工具请求；`device.control`、`process.manage`、`session.manage`、`program.adopt` 用于普通语言函数中的原生效果。Team 成员与函数作用域可以缩小项目授权，不能扩大它。设备列表仅列可信宿主注册的静态名字，不证明连接或硬件就绪。

## 编辑与阅读

日常编辑先掌握下面几个动作；后续说明列出它们对草稿、版本和语义的具体影响。

| 需要什么 | 直接操作 | 何时写入项目 |
| --- | --- | --- |
| 补全名称或查看参数 | “智能提示”／`Ctrl-Space`；参数提示 `Ctrl/Cmd-Shift-Space` | 选中候选只修改草稿 |
| 排好代码再保存 | “格式化”／`Shift-Alt-F`，然后保存 | 手动格式化仅改草稿；保存成功才提交 |
| 保存时自动排版 | 保持“保存时格式化”勾选，按 `Ctrl/Cmd-S` | 格式化成功且文本变化时提交当前模块 |
| 调整代码颜色 | 编辑区“配色”选择深色、纸面或高对比 | 只保存浏览器显示偏好 |
| 检查来源和诊断 | “检查”“导航”，或悬停标识符 | 分析不执行程序、不提交源码 |


- 注释、字符串、数字、关键字、类型、变量、参数、属性、函数与运算符按类别着色；布尔值使用关键字样式。赋值符号参与着色。语义范围来自真正的语言分析，浏览器不维护另一份关键词和类型清单。分析尚未返回时只显示基础词法颜色。
- 主源码、工作流函数体和只读代码阅读使用同一套语义配色；同一角色在不同视图中保持一致，选中、当前行与打印时仍保持文字可读。赋值目标与读取位置按已解析的绑定角色着色，非法赋值仍保留原有诊断。颜色区分名称的实际角色，不根据名称猜测：例如与原生函数同名的局部变量仍使用变量样式。注释使用较安静的颜色，源码内容不因配色变化而改动。
- 默认深色配色以紫色表示语言结构，暖金色表示函数与智能体，青绿色表示类型，蓝紫色表示属性，暖橙色表示参数，浅蓝色表示变量，绿色表示字符串，粉色表示数字；行号、分隔符和注释降低视觉权重。函数类型的参数仍按参数身份着色；别名和遮蔽依据真实绑定，不能按名字猜测。智能体当前作为可调用函数使用函数色。编辑后的语义分析尚未返回时，两种编辑器共用字符串、注释、数字、运算符和分隔符的临时词法着色，名称保持中性，避免用旧语义误导。
- 主源码编辑器按可用宽度视觉折行，长工作流调用也能阅读；视觉折行不改变源码、光标偏移或保存内容。回车缩进、括号配对、括号匹配、撤销/重做和搜索由编辑器处理。
- 输入时自动显示代码补全；也可点编辑区的“智能提示”或按 `Ctrl-Space` 主动打开。主源码与函数体编辑器共用补全适配器，候选、导入路径、成员和关键字参数来自语言分析服务；补全替换完整名称，光标位于名称中间也不会残留旧后缀。每次输入重新查询当前上下文，切换文件、项目或依赖后不能采用旧候选；输入法组合输入期间不采用补全。悬浮信息和参数提示来自同一服务，包含可见符号、函数签名与已知类型。输入调用或移动光标时显示当前可确定的参数；`Ctrl/Cmd-Shift-Space` 可主动刷新。已知导入、别名、绑定方法、宏和可调用的智能体值使用真实签名；动态展开长度未知时不猜测参数位置。类型提示是保守分析；`Any` 或未知类型不代表静态类型推导已经完成。
- 语法诊断显示文件与位置。尚未写完的程序可以保留在草稿中；补全可在部分源码上工作，分析不会执行工具、智能体或用户函数。
- 格式化按语句和嵌套结构换行，长调用、列表、记录和参数列表根据目标宽度展开，保留注释和字符串。IDE 默认目标 88 列、缩进 2 空格；宽度不是硬截断，不拆开长字符串、注释和标识符。格式化前后检查语法树语义一致，不能格式化的源码保持原样并显示错误。
- 画布创建或修改工作流定义时，服务端使用同一格式化器生成可读源码，网页、SDK、HTTP 和文件工作区读取同一份文本，不追加第二次保存。只调整节点坐标时保留已存源码、注释和手动排版；源代码编辑保持原文，除非明确格式化。接近单文件 100000 字符或程序包 1 MB 上限时，如果仅排版扩展会超限，生成器保留已经验证的紧凑形式，不提高解析限制。
- 编辑区工具栏中可直接找到“智能提示”“格式化”和“保存时格式化”。主源码编辑器的“保存时格式化”默认开启，可关闭，选择保存在当前浏览器。它在保存源码改动时格式化当前模块；在源码视图中，即使文件已经保存，按保存也会排版当前模块。只有文本实际变化才提交新版本，重复保存已排版的文件不会增加版本。不会批量格式化其他模块，也不会在打开文件或空闲时自动改稿；结构 IR 和工作流配置沿各自保存流程处理。运行、调试和文件操作前仍会保存已有草稿；源码有改动时保留保存时格式化。已保存文件只有明确点击保存、使用保存菜单或按 Ctrl/Cmd-S 才进行自动排版；运行、调试和文件操作不会因为内部保存而重新排版已保存源码或增加版本。手动格式化只修改当前草稿，保存后才提交项目版本。空白调整保留选区对应的文本位置，格式化有独立撤销边界；旧方言显式迁移等非空白修改使用保守选区映射。切换项目或文件、更新依赖与再次编辑都会使旧分析或格式化响应失效。主源码和函数体编辑器在输入法组字期间暂缓格式化与自动格式化保存，并显示提示；已发出的格式化请求若跨过组字开始事件，即使组字结束且文字未变，旧结果也不会写入。完成组字后可重新格式化或保存。

记录中的字段名（包括带引号、转义和中文的静态键）按属性色显示，字符串值保留字符串色。例如 `{"role": "worker"}` 中 `"role"` 与 `"worker"` 颜色不同。此区分来自解析后的记录／模式节点，未完成输入时仅使用保守词法颜色，不按字段名称或固定文本猜测。

主编辑区和函数体“格式化”旁，以及文档／报告的代码工具栏中，都可通过“配色”选择深色、纸面和高对比；也可在“编辑”菜单或命令面板中选择“代码配色”。这些入口共用一个面板，可展开颜色说明查看 11 类语义角色。面板内的实时示例通过同一个语言分析服务着色，首次打开时才分析，不运行代码或调用模型；分析不可用时保留原始示例，再次打开可重试。关闭面板后返回原入口；入口已移除或用户已转移焦点时不抢回焦点。选择同时用于主源码、函数体、参数签名面板和只读代码块，当前参数使用参数语义色、加粗及边框共同标识，只调整代码区域的外观；当前文件、选区、撤销记录和输入法组字保持原样。偏好保存在当前浏览器，同站点其他标签页会同步；浏览器禁止存储时仍可在本页切换，重新载入后采用默认深色。切换文件也沿用当前配色，打印使用独立的纸面颜色；这些操作不会保存或运行项目，也不修改语言的语义识别规则。

组合／递归契约的构造函数、引用名与诊断字段使用同一原生元数据。契约别名注解保留原拼写，载荷类型保守为 Any；补全不会执行 contract_recursive、验证引用绑定或展开递归结构。实际错误由运行时报告，见[组合契约](CONTRACTS.md)。

主源码编辑器快捷键：`Ctrl/Cmd-S` 保存，`Ctrl/Cmd-Enter` 运行入口程序，`Ctrl-Space` 补全，`Ctrl/Cmd-Shift-Space` 参数提示，`Ctrl/Cmd-F` 搜索，`Shift-Alt-F` 格式化。格式化失败时保留源码并显示错误；保存或运行不会绕过该失败继续提交。

## 按声明导航

代码旁的“导航”或 `Ctrl/Cmd-Shift-O` 显示当前文件的真实声明。可按名称筛选，用键盘选择条目，定位名称或选中完整声明；选区随后直接进入现有“与助手编程”的草稿上下文，不自动发送、保存或运行。

大纲来自同一次语言分析中的原始语法树，包含函数、智能体、类成员、宏、数据及构造器等声明，按语法容纳关系分层。声明种类描述源码写法，类型与签名保持原分析的保守结果；不执行装饰器、宏、属性或智能体来猜实际对象。引用模板和未能确定归属的匿名函数体不伪装为外层具名函数的声明。部分源码或达到限制时明确显示不完整状态；它不是整个工程的调用图或完整运行时作用域。

大纲、诊断和引用条目携带生成时的草稿快照。编辑、切换项目或文件、修改入口或方言后，过期条目不能把光标移动到新代码；分析失败也不会显示为没有问题。诊断允许在文件末尾定位零宽错误，文件不存在或范围不合法时保持当前选区。导航保留其他模块草稿、撤销历史和未发送对话。

## 工作流函数体

工作流画布中，选中函数节点后，配置面板的“函数体”使用代码编辑器，提供相同语言服务的语义颜色、补全、悬停、参数提示和诊断。`input` 是节点收到的值；导入解析使用项目模块包。未改动源码保留已保存的方言，编辑后按当前方言检查。提示与格式化不会运行函数或调用智能体。

面板提供“智能提示”“参数提示”和“格式化”按钮，支持 `Ctrl-Space` 补全、`Ctrl/Cmd-Shift-Space` 参数提示、`Ctrl/Cmd-F` 搜索和 `Shift-Alt-F` 格式化。函数体格式化目标为 72 列、2 空格缩进，保留注释、字符串、选区和独立撤销边界；长字符串或标识符不会被截断。

函数体自己的“保存时格式化”默认开启，可关闭，选择保存在当前浏览器，与主源码编辑器的选项分开；浏览器不允许存储时，在当前页面内保留选择。保存时只处理当前可编辑、已修改的函数体，不遍历其他节点。输入和格式化仍属于配置草稿；“应用配置”更新本地节点，保存才提交项目版本。切换节点、项目或收到远端修改时，原有草稿与版本冲突保护继续生效，迟到的响应不能覆盖新内容。未加载编辑器资源时保留普通文本输入。JSON 配置、任务输入、提示词和运行结果是数据，不使用 Chaos 代码编辑器。

## 小屏编程与面板切换

宽度不超过 850px 时，源码编辑器使用活动栏旁的主要空间，文件列表按需浮动展开，默认显示源码。“编程助手”切换到助手面板；“返回源码”或 Escape 回到编辑器。面板切换不重建代码文档，保留当前文件、源码草稿、选区和未发送的对话输入，也不保存或运行程序。

小屏的活动栏“文件”按钮展开或收起模块目录；快速打开命令仍可直接切换文件。桌面助手默认关闭；窗口由桌面缩小时自动回到源码，重新放大时恢复你在桌面明确选择的助手展开状态。高亮、补全、参数提示、格式化、保存和运行仍使用同一语言服务及版本化项目，不另设手机端语法。

## 文件与目录

文件树按包内路径组织 `.chaos` 模块。可以新建文件、打开多个文件、重命名、删除和选择入口。切换源码文件保留各文件草稿，即使当前代码暂时无法解析也不会丢失；运行与提交仍要求整个程序包有效。

“新建目录与入口模块”会创建 `目录/__init__.chaos`，初始内容为 `export {};`。目录由模块路径组成；当前项目包不存储空目录或任意二进制资源。目录重命名作用于所有子模块，文件移动时会同步修改真正的 `import` 路径，并保留普通字符串与注释。删除正在使用的依赖或包含程序入口的目录会被拒绝。

文件树操作使用版本检查。发生远端修改时，先处理版本冲突；正在输入的内容继续作为本地草稿保留。文件树显示当前程序包中的模块，不是任意宿主磁盘浏览器。目录项目已将本目录文件通过原 Workspace 协议连接到这个视图；有效修改按周期同步，语法错误等待修正，双端冲突保留双方并停止同步。原独立服务仍可按[实时一致性指南](REALTIME.md)使用 checkout/watch；两种路径都不读取编辑器未保存的内存草稿。

## 系统智能体对话

编程助手用于修改当前程序；向执行中的程序补充要求，应使用“运行：追加当前运行指导”。独立的工具任务在 `/control` 提交。三种入口的用途见[用户指南](USER_GUIDE.md#先选对交互入口)，不会因为输入了相同自然语言而自动互相转交。

1. 在当前文件旁点“与助手编程”，或从活动栏“助手”、命令面板打开助手。先核对上下文条里的文件、选区、草稿和版本，再描述修改目标并点“发送 ↑”。打开面板或选择代码不会发送模型请求。
2. 展开回答中的“执行过程”查看当前公开阶段；任务运行期间可以继续阅读和编辑文件。下一轮的“发送”和“新对话”在当前任务结束前禁用；可以先写好下一条输入，或点助手自己的“停止”。
3. 任务完成后查看回答、逐文件修改、提案检查结果和入口变化。只有需要采用时才点“应用并保存”。保存成功后再用顶部“运行”执行入口，核对实际结果；提案通过结构检查不等于已经满足业务需求。

服务读取系统配置中继承或为 `ide` 指定的模型连接，使用独立原生 SDK harness。首次配置见[模型配置](MODEL_CONFIGURATION.md)，可参考[模型智能体示例](MODEL_EXAMPLES.md)。

发送冻结当前完整源码草稿、入口、各文件方言及 UTF-16 选区，包含未保存模块；发送本身不保存项目，也不等于点击运行按钮。服务通过同一语言分析器提取有界诊断、符号和选中文本，尚未完成的语法也能作为对话输入。智能体通过结构化草稿工具生成候选；普通回答或 Markdown 代码块保持为回答。项目权限、画布配置、结构 IR 等其他未提交改动，以及远端版本冲突，需要先按现有流程处理。

“执行过程”逐条追加最近40条公开记录，包含任务阶段、路由和工具状态；它展示实际发生的执行摘要，不承诺逐 token 展示模型回复。界面保留相同提案的差异展开状态和阅读位置，靠近底部时才继续跟随新内容。最终回答和差异可以先出现，随后显示“结果已返回 · 正在同步最后的执行事件…”；最后的完成、失败、取消或中断事件同步后才结束本轮观察。

短暂断网时，已获得任务 ID 的当前任务继续被跟踪，取消入口、源码草稿和未发送的下一条输入留在当前页面；恢复后补读事件，不必重新提交。停止请求只有送达后才可能生效。浏览器前进／后退若恢复了缓存页面，实时订阅会重新连接；普通刷新或浏览器丢弃页面内存不保证恢复未保存输入，刷新前请保存或导出源码，并另外保留尚未发送的文字。服务保存已发送的输入和候选，打开助手可重新读取近期对话；同一会话续轮仅在输入草稿一致时接续此前候选。这与保存浏览器草稿、选区或所有展开状态不同。

文件比较只列出智能体相对提交草稿的修改。应用时，服务核对提交的草稿快照、当前内容和项目基准版本；期间修改源码或入口后，旧提案不能直接应用，应保留新草稿并基于它重新请求。移动光标或切换打开文件不改变内容身份。应用请求进行中继续输入的新内容仍保留为草稿，按原远端冲突流程处理。一次成功应用会向源码、结构视图和其他订阅客户端发布同一个新版本。

IDE 草稿工具可在有限预算内检查与试运行语言程序及 fixtures，项目授权仍有效；它不直接执行宿主 shell。独立代码解释器、浏览器等工具任务见[后台任务控制台](HARNESS.md)。运行进度、指导回执及流恢复契约见[实时交互](REALTIME.md)。

编辑器支持 async fn*、async for 和 AsyncGenerator 类型提示，并识别导入模块的公开宏。`Alias.name!()` 的成员提示来自实际模块声明；语言分析不执行宏、智能体或工具。结构视图与格式化保留这些原始语法，通过保存版本和 SSE 同步到无界面调用者。

## 类和智能体组件编辑

编辑器依据真实类 AST 提供类名、成员、继承和绑定方法参数提示；类体结构表单使用合法成员声明。成员赋值保持为独立结构节点，源码与 IR 使用同一解析和校验规则。动态添加的成员或运行时基类表达式可能没有完整静态提示，实际运行仍按语言契约检查。详细语法见[对象与组件](OBJECTS.md)。

## 装饰器与属性提示

实例／元类属性拦截沿共享静态分析：存在 __getattribute__ 的普通成员降为 Any，不把存储方法签名或声明位置当作实际返回值；__getattr__ 可替换缺失描述符结果，未知动态名称不会被猜测。default_* 提供原生参数提示并显式委托默认逻辑。语言中的 dir 可执行 __dir__，IDE 补全不会调用它或任何属性钩子，见[属性协议](ATTRIBUTE_PROTOCOL.md)。

源码与结构 IR 保留 `@` 包装、装饰器表达式顺序及内部声明。静态分析只根据实际绑定身份识别内置 staticmethod/classmethod/property；同名局部变量不会被当作内建装饰器。未知用户装饰器不会运行，也不假定保留原函数签名或类身份，因而相关结果可能显示 Any。

已识别的静态方法保留全部参数，类方法隐藏已绑定的 cls，属性显示 getter 的返回类型。装饰后的实际行为仍由运行时验证。结构编辑、API/SDK 修改与页面保存继续使用同一版本化项目和 SSE。

## 用户描述符与删除操作

用户协议由普通类方法组成，结构编辑器和源码使用既有 AST；`delattr(object,"name")` 是普通函数调用。删除程序树节点与运行时删除对象属性是不同操作。

分析器按已知名义类和原始 MRO 成员识别协议，只采用可证明的声明返回契约；未知、可变或经过不确定装饰器的行为保留 Any。Class 成员的存储类型与实例访问结果分别处理。分析和补全不会执行 getter、deleter 或命名通知，也不推测模型输出。

运算协议使用现有 binary/unary/call 与普通方法定义，源码和结构编辑共享一棵语法树。补全包含 `NotImplemented` 常量及新内建；结果类型仅在可证明时显示，未知反向分派或可变方法返回 Any。分析器不会执行用户协议；因此分析源码不会触发模型或工具。协议函数体仍可设置断点。

用户迭代方法继续使用普通类和函数节点；for、async for 与 yield from 的源码/IR 表示保持兼容。补全识别 Iterator/AsyncIterator 及 next 记录中的 done/value；一般产出元素保持 Any，不把生成器的最终返回注解当作每个元素的类型。代码分析不获取游标、不推进流，也不调用 Agent。

当前编辑器区分条目下标与属性访问，支持切片起点、终点、步长的独立添加与省略，并为声明的条目协议提供保守提示。检查和调试预览不会调用 getter。项目按文件记录语法版本；未改模块使用原版本，编辑后的模块采用当前版本，旧文件格式化会显式保留旧访问语义。

## 页面中的代码阅读

在线文档和导出的离线文档使用相同预渲染高亮。代码围栏的标签决定语言：`chaos` 由本语言分析器着色，`python`／`py` 由 Python 标准库词法器着色；`sh`、`shell`、JSON 等其他标签当前显示原文。页面不会根据代码里的词语猜测语言。Chaos 提示来自当前片段中可解析的声明与引用；跨围栏示例没有共享词法环境。

只读代码默认保留原始排版。“自动折行”只随容器宽度换行；“格式化阅读”使用与 IDE、CLI 相同的语法树格式化器生成阅读副本，按语句和嵌套结构重新排版，再分析副本的语义范围。切换后点“原始排版”回到原文。它保留注释和字符串内容，不执行代码，不修改项目、候选、运行快照或文档示例；复制按钮始终复制完整原始源码，导入候选也使用原始源码。行号、工具条和视觉折行不混入剪贴板。

格式化阅读仅针对可分析的 Chaos 代码。动态预览首次请求后缓存阅读副本；请求失败或源码无法格式化时保留原文并显示状态，源码更换后迟到的响应失效。文档在服务端预计算阅读副本；有效且排版有变化的片段才提供切换，静态导出包含相同副本，离线阅读无需分析 API。超过代码展示分析上限的片段、关闭分析的视图和其他语言不提供这一功能。

有类型或签名信息的标识符可悬停查看，也可点击（含触屏轻触）打开提示。工具条“代码提示”打开当前代码的提示面板，使用“上一项”“下一项”浏览；代码区域获得焦点时，左右方向键切换提示，Escape 关闭。提示仅来自实际声明和已解析引用，未知类型保持保守，不执行 getter、宏或智能体。

候选／历史比较、助手修改和生成模块预览共用这一只读组件。候选比较携带实际模块包和逐文件方言；助手的独立片段缺少完整导入上下文时仅提供保守语义信息。只读展示不会自动保存或采用提案。

“查看执行快照”可选择该次源码运行保存的模块，查看版本、语义颜色和提示。分析使用该次运行的模块包及逐文件方言，当前项目的新定义不会改变历史提示。调试器的只读源码保留当前暂停行标记；带当前行标记的视图不提供格式化阅读，以保持真实源码行号。普通执行快照可以切换阅读排版，保存的原始快照不变，也不写回当前草稿。

## Channel 编程与调试

Channel 注解、五个通信内建函数、接收完成值及状态字段参与同一语义着色、补全、参数与悬停帮助；自动格式化保持源码／结构语义。调试暂停显示真实通道容量、缓冲数量和等待任务身份，恢复运行后清除旧快照，不展示消息正文。在线／离线文档同样提供代码颜色、提示、换行与原文复制。见[消息通信](CHANNELS.md)。

文档和普通代码预览的悬停提示同时覆盖声明与已解析的引用：内建调用、用户函数、别名和可确定的成员复用分析器的作用域绑定。未解析引用不会凭关键词填入假签名。服务端渲染、浏览器动态预览与离线导出使用相同提示数据；HTML 转义和原始源码复制保持不变。

### 直接表达式提示与原生等待

成员补全与参数帮助读取分析器中真实接收者／可调用表达式的信息，支持调用结果、括号和 await 后的记录；不必先额外声明临时变量。分析恢复只用于不完整编辑文本，不改变运行时解析器，也不执行函数、宏或 getter。Task／TaskGroup／Channel 与等待函数的签名和数据形状来自共享原生规范；不确定的可变或动态调用仍保持保守。计时与等待任务在暂停调试时显示同一调度器的 timing，见[等待指南](WAITS.md)。

## 选择候选与参数提示

ChannelCase 注解、send_case／receive_case／case_info／channel_select 使用共享原生签名，直接 `(await channel_select(cases)).` 的成员补全来自真实 AST 值形状；不运行构造函数或用户代码。代码预览、语义颜色、格式化保存和结构编辑沿用同一来源。暂停时选择任务卡片显示实际候选通道、总数、截断与选中序号，恢复后清除快照，见[选择指南](SELECT.md)。

## 可迭代函数组合

map/filter/fold/any/all 和 apply 的签名由共享内建元数据驱动；同步输入以 Any 表示静态未知，运行时仍校验 iter 协议。动态星号展开后的参数位置保持未知，分析不会推进生成器或调用用户协议。代码高亮、悬停、参数帮助、格式化与源码／结构保存复用同一词法和 AST。详见[函数组合](FUNCTION_COMPOSITION.md)。`std/iter` 的补全、参数、Generator／AsyncGenerator 提示来自安装包内真实函数源码；没有按导出名称另列的签名规则。分析不消费流，宏与结构编辑仍用同一 AST，见[惰性流](STREAMS.md)。

## 推导式的编辑支持

列表／记录推导与生成器表达式使用与运行时相同的 AST。投影虽然写在 `for` 前，仍能引用所有子句绑定；每个来源只看见此前绑定。高亮、补全及悬浮遵循这个作用域，格式化保留注释和字符串并验证 AST 等价。结构面板只在推导内接纳合法子句，源码与 Program 继续使用既有版本同步协议。见[推导式](COMPREHENSIONS.md)。

## 解构目标的语义编辑

声明、循环、同步／异步推导、批量赋值和资源 `as` 的结构目标共享已有模式编辑器。批量赋值叶子引用原符号并检查原有契约，不创建新声明；资源叶子是新局部只读绑定。三个新增结构节点只允许列表、记录或构造器作为目标根。叶子名字进入真实作用域并提供语义高亮、悬浮、补全与定义定位；记录字段名和绑定名分别处理。右侧不会提前看见新绑定，推导投影可以看见全部子句绑定。未知类型保持保守提示。格式化继续保留注释和字符串并验证语义不变。示例与限制见[解构绑定](PATTERN_BINDINGS.md)。

## 结构化函数参数

`fn handle(input as {task: task, .._}: Record)` 的输入槽与叶子由同一个函数作用域提供高亮、补全、悬浮和定义位置。签名显示模式，但调用提示只推荐公开标签 `input`，不会把 `task` 当成第二个可传参数。格式化保留模式、默认值和注释；Program 结构中的参数 `pattern` 使用已有模式节点编辑。分析不会调用智能体或用户 getter，未知字段类型仍保守显示。详见[参数解构](PATTERN_BINDINGS.md#函数参数中的模式)。

## 并发计划编程（0.39）

`plan` 的代码提示包含 `max_concurrency: Int = 1`；构造结果仍为 Plan，`run_plan` 为冷 Task。模式编辑器可设置同一并发上限，并按 revision 保存；并发 SDK 修改不会覆盖未保存草稿。执行面板按实际运行和 Plan 调用区分步骤状态与任务身份。

模式导出源码继续使用公共代码显示组件提供高亮，导入 IDE 后使用相同解析器提供补全、诊断与格式化。格式化只调整源码布局，不替换字符串或依据自然语言关键词猜测程序；保存和图形编辑继续验证同一语义结构。示例见[并发计划](AGENT_MODES.md)。

## 定义导航与外部编辑器

在源码中的标识符处按 F12 或使用“转到定义”，可定位到当前多文件草稿中的声明。导航保留未保存内容，并选中目标名称。模块成员跳转使用目标模块的源码位置；动态未知来源或内置运行时值可能没有可打开的声明。过期异步响应不能切换用户已经继续编辑的文件。

外部编辑器通过 `chaos lsp` 使用同一解析器、语义颜色、参数提示、格式化及定义来源。编辑器内未保存内容用于其语言服务；只有保存并执行 workspace 同步后才成为服务中的项目修订。详见[语言服务器](LANGUAGE_SERVER.md)与[实时同步](REALTIME.md)。


## 资源工厂的提示与阅读

`std/context` 资源装饰器的参数信息来自真实函数声明，能确定的 yield 值用于 with 绑定的类型和成员提示。别名与模块导入遵循词法绑定；不会仅凭函数名称推测资源类型。装饰器、yield、类型注解、变量和赋值沿用语义着色；格式化可展开紧凑源码，同时保留注释及字符串。LSP 与内置页面调用同一分析和格式化实现。示例见[函数定义资源](CONTEXTS.md#用函数定义资源contextmanager)。


## 动态资源栈提示

## 正常完成分支

结构面板支持 loop_else 和 try_else 的受限控制结构选择及 otherwise 块编辑，finally 的保护结构也接受 try_else。源码修改、结构修改和外部 API 更新继续遵守版本比较与实时同步。完成分支的高亮、补全、变量重命名和类型提示来自其实际外层作用域，不泄漏循环目标或 catch 名称；可能产生不同类型时保守显示 Any。格式化保持 else 关联、注释及原语义，详情见[完成语义](CONTROL_COMPLETION.md)。

## 异常分支的编写与排序

## 原生函数与追踪

`compile_function` 保留目标函数的参数、返回和调用提示，`compile_info` 提供结构化字段补全；别名、模块导入、装饰器和格式化沿用同一语言定义。运行配置的“逐表达式追踪”默认开启并保存浏览器偏好，记录每个表达式时原生函数使用解释器。关闭该选项后仍记录任务和工具事件，同时允许受约束函数进入 LLVM 后端；它与 SDK／HTTP 的 `trace` 选项对应。详细范围见[原生函数](NATIVE_FUNCTIONS.md)。普通编译函数的调用、参数模式与同步 for 仍用原 AST，签名、循环变量提示和源码／IR 编辑共用原语言服务；分析不会运行默认表达式、执行回调或推进游标。`compile_flow_info` 的原字段补全可检查实际 nativeResumes／portableResumes，启用调试或追踪时从当前 PC 便携续接。见[原生结构控制流](NATIVE_FLOW.md)。
