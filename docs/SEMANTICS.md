# Chaos：函数、智能体与图环境的语义

本文对应 language core v1，解释当前语义和抽象论证。完整语法与实例以[语言参考](LANGUAGE.md)为准，资源上限集中列于[进阶编程](ADVANCED.md#递归与有限执行预算)。软件包版本由 `chaos/version.py` 管理。language core v1 是核心规范名称，与逐文件保存的解析方言版本不同：当前新文件使用 languageVersion 2，历史文件可继续使用 1。这里区分计算表达能力、可检验的结构路径覆盖、可审计的执行过程三个不同性质，不将“途径完备性”预设为一个既有数学定理。

## 1. 统一对象模型

可调用单位接收参数序列并产生值；一元情形记为 `f : Value → Value`。完整程序则是带入口文件的封闭模块包。闭包、高阶函数、工具包装函数和智能体都是可调用值。

纯函数计算由 `(expression, environment, budget) → value` 描述。效果函数还接收执行上下文：`(input, state, capabilities, budget) → (output, state', events)`。智能体是带有限行动协议的效果函数，工具是注册的原子操作。图编排提供这些函数的组合关系，而不是另造一套表达式计算器。

基础值包括有限整数、有限浮点、字符串、布尔、null、列表、不可变元组、字符串键记录、闭包、原生函数、智能体声明及 data 类型描述值；语言还提供类、实例、描述符、任务、生成器/异步流句柄和 NotImplemented 拒绝单例，完整契约见语言参考。data 实例用带名义身份的记录协议表示。实际实现有资源界限；数学抽象去掉界限后使用无界自然数及有限长度但无固定上限的数据结构。

智能体可建模为机器：

`A = (Q, q₀, I, O, M, T, δ, F)`

- `Q`：observing / thinking / tool action / completed / failed / cancelled。
- `I, O`：输入与输出值；`M` 为上下文与项目持久记忆。
- `T`：获授权的工具集合。
- `δ`：本地策略或模型提出的转移，再经过运行时能力与预算校验。
- `F`：明确的完成、失败或取消状态。

“智能”在 δ 的决策策略；可计算性来自外围的语言和状态转移机制。模型可能具有随机性，也可能无法完成任务。增加提示词、角色数量或工具数量，不会自动证明图灵完备、路径完备或推理正确。

## 2. 语法核心

以下是帮助定位各类结构的语法概览；省略词法、列表分隔和优先级产生式的细节，实际接受的语法由 `Parser` 及[语言参考](LANGUAGE.md)规定。

```text
program      ::= (statement ";"?)*
statement    ::= ("let" | "var") name (":" type)? "=" expression
               | name "=" expression
               | "fn" name parameters ("->" type)? block
               | "rec" "{" functionDeclaration+ "}"
               | "agent" name record
               | "data" name "{" variants "}"
               | "import" string "as" name | "export" "{" names "}"
               | expression
expression   ::= literal | name | list | record
               | "fn" parameters ("->" type)? block
               | "if" expression block "else" (block | ifExpression)
               | "while" expression block ("else" block)?
               | "for" name "in" expression block ("else" block)?
               | "break" | "continue" | "return" expression?
               | "do" block | "throw" expression?
               | "try" block catchClause+ ("else" block)? ("finally" block)?
               | "try" block "finally" block
               | "match" expression "{" guardedPatternArms "}"
               | expression "(" arguments ")"
               | expression "[" expression "]" | expression "." name
               | unary expression | expression binary expression
parameters   ::= "(" parameterList? ")"
parameter    ::= name (":" type)? ("=" expression)?
               | "*" name (":" type)? | "*" | "**" name (":" type)?
argument     ::= expression | name "=" expression
               | "*" expression | "**" expression
catchClause  ::= "catch" catchPattern ("if" expression)? block
block        ::= "{" program "}"
```

`import/export/data` 仅限模块顶层；`return` 仅限函数；`break/continue` 仅限当前函数内的循环。模式包括通配、绑定、标量、构造器、列表、元组与记录及剩余模式。循环 else 不位于该循环的控制范围内；其 break/continue 只能指向外层循环。

具体优先级从低到高：`|>`、`||`、`&&`、`== !=`、`< <= > >=`、`+ -`、`* / %`、一元、调用和索引。管道 `x |> f` 等价于 `f(x)`，并非自动把参数插入 `f(a)`。需要预先绑定参数时使用 `partial` 或 lambda。

参数列表中带默认值的位置参数之后不能再声明必需位置参数；`*` 后为仅关键字参数，`**` 收集参数必须最后。调用中的位置实参和 `*` 展开须先于具名实参和 `**` 展开。这些顺序限制属于语法验证，不由运行时猜测调整。

参数与返回注解是动态契约，可引用闭合的 Union 等组合契约；本版没有 Hindley–Milner 推导、完整静态类型推导、通用泛型类型语法或效果类型推导。函数主体最后一条语句产生默认返回值，也可显式 `return`；空块为 null。

## 3. 求值规则与纯度

用 `ρ ⊢ e ⇓ v` 表示表达式在环境 ρ 下求值为 v。求值是严格、从左到右的。

- 变量：`ρ ⊢ x ⇓ ρ(x)`，未绑定即报错。
- 闭包：lambda 捕获创建时已有 let 值的快照与 var 的共享单元。后续局部声明不会进入旧闭包。
- let：同一作用域只可绑定一次。内层可遮蔽外层；绑定本身不可赋值。
- var：更新最近的同名可变绑定并重新检查契约；遇到同名 let 时拒绝赋值。
- 命名函数：先捕获已有环境，再在闭包私有环境中绑定函数自身，支持自递归。无隐式函数提升；`rec` 先共同绑定整组函数以支持互递归。
- 默认值：函数定义时按参数声明顺序，在外层环境求值默认表达式一次并检查参数契约。缺省调用复用这些值，不在调用帧内重新计算。
- 应用：先求值函数，再按源码顺序求值位置、具名及展开表达式；`*` 按同步迭代协议收集位置值，`**` 仅接受 Record。收集后按位置或名称、默认值、剩余位置和剩余名称规则绑定，再检查契约；缺参、重复、未知参数及类型失败在主体之前报告。
- 剩余参数：`*rest` 绑定完整 List，`**options` 绑定完整 Record，契约作用于这两个容器而非逐项元素；仅关键字参数不能由位置实参填入。
- 高阶调用：`apply` 显式提供位置列表和具名记录；`partial` 连接已绑定与本次位置参数，本次具名值覆盖已绑定的同名值；`compose(f,g)` 将全部实参传入 g，再把单个已求值结果传入 f。最终绑定、效果权限及尾调用契约仍由同一解释器处理。
- if：条件必须为 Bool，只求值被选择的分支。
- `&& / ||`：严格 Bool、右侧短路；右侧尾位置保留 Bool 返回约束。
- 原生容器：`set / append / tail / map` 返回新值。List／Tuple／String 的 `+=` 将新连接值赋回变量，不修改旧容器；对象原位协议见[增强赋值](AUGMENTED_ASSIGNMENT.md)。
- finally：保护块（或 try/catch 及其可选 else）与清理块分别从同一外层环境建立独立局部作用域。正常完成、LanguageError、return、break、continue 先完成清理再恢复待决结果；清理的正常值丢弃，清理的 return/throw 可替换普通待决结果。嵌套清理内层先执行，尾返回调用先求值再清理。ResourceLimit/ExecutionControl 直接传播并跳过清理；清理期间发生的硬控制也不能被普通控制覆盖。
- 正常完成：循环 else 只在条件为 false 或迭代耗尽时执行；try else 只在保护体正常完成时执行。两者的完成块以外层环境建立独立作用域，执行值成为表达式结果。catch 结果不触发 else，else 错误绕过同级 catch；无 else 的旧行为保持不变。详情见[完成语义](CONTROL_COMPLETION.md)。
- 尾调用：主体末表达式、if/match/do 尾分支、显式 return 和短路右侧支持 trampoline；尾调用链保留所有返回契约。try 与 finally 的动态处理范围需解析尾调用，跨处理器或清理范围的递归仍可能增加普通调用深度。

工具由调用时的执行上下文校验。`partial(tool, name)` 是一等工具函数，但不能把高权限环境的可调用值转交给另一个解释器以绕过权限。当前版本显式拒绝跨解释器的 Function/Native/Agent；`apply/partial/compose` 也不能绕过这一身份边界，图边仅传 JSON 数据。

函数节点默认纯计算，禁用智能体效果；配置 tools 后可显式调用相应工具。用户源码程序是授权的效果入口。能力继承指调用上下文的授予集合与智能体声明的交集；图层级本身不自动把父节点的工具清单当作子节点工具清单。

## 4. 抽象计算完备性的构造论证

抽象语言可表达两寄存器机的配置 `C=(pc,a,b)`。每条指令可编码为 `step(pc,a,b)` 的条件分支：

1. `INC r; GOTO j`：把对应寄存器加一，尾调用 `step(j,a',b')`。
2. `DECJZ r; GOTO j,k`：寄存器为零时跳到 j，否则减一并跳到 k。
3. `HALT`：返回寄存器记录。

无条件跳转可直接编码为 `step(j,a,b)`，不会依赖顺序执行规则。两计数器机器的指令集细节会影响通用性；本文采用显式跳转的模型，相关背景参见 Dudenhefner 的原始研究 [Certified Decision Procedures for Two-Counter Machines (FSCD 2022)](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.FSCD.2022.16)。

因此任意有限合法指令表都能变成有限的嵌套 if 与递归函数，也可以由同一个普通 Chaos 函数解释 List／Record 表示的指令。配置关系取“相同 pc、相同两个非负整数寄存器”：inc 更新指定寄存器并转到 next；decjz 依零值选择 zero，否则减一并转到 nonzero；halt 返回当前配置。初始配置对应，每一步保持这个关系，由归纳得到任意有限步执行前缀的对应；停机配置的寄存器结果也一致。

`examples/counter-machine.chaos` 保留下面的转移示例，同时导出 `run(program,a=0,b=0,pc=0,fuel=10000)` 以替换指令表。合法指令是 `{op:"inc",register:"a"或"b",next:位置}`、`{op:"decjz",register:"a"或"b",zero:位置,nonzero:位置}` 与 `{op:"halt"}`；所有指令（包括未到达行）在模拟前验证。返回记录含 status、pc、a、b、steps；fuel 用尽得到 fuel_exhausted，属于程序自行选择的有限前缀。可显式增加 fuel，或用返回配置继续下一段；真实宿主步数／时间预算仍独立生效，ResourceLimit 不被伪装成停机结果。

在采用上述两寄存器机通用计算能力这一标准前提下，这个有限编码与逐步对应给出抽象核心可模拟通用计算的构造。有限程序的运行和测试只验证具体编码、分支与组合路径，不能单独证明全部程序的语义保持或终止性；本文尚未提供证明助手机械化验证的定理。发布验收仍按[语言核心合同](LANGUAGE_CONTRACT.md#h-一次发布的有限验收)逐项核验。

示例（把 a 的计数转移到 b）：

```chaos example=semantics-counter-machine
fn machine(pc, a, b) {
  if pc == 0 {
    if a == 0 { machine(2, a, b) }
    else { machine(1, a - 1, b) }
  } else {
    if pc == 1 { machine(0, a, b + 1) }
    else { {a: a, b: b} }
  }
}
machine(0, 37, 5) // {a: 0, b: 42}
```

测试验证上述机器实例、递归、尾递归和条件行为。这不等于通过有限测试证明整个解释器正确。实际有界实现并不满足无限执行或无限存储假设，预算耗尽会返回明确错误。

不可能通过通用静态检查判定任意此类程序对所有输入都终止。本系统不把“智能体最终会找出正确途径”作为可保证的系统性质。

## 5. 图的路径覆盖证书

图 `G=(V,E,H)` 中，V 是原子节点，E 是数据边，H 是 parentId 管理关系。平台节点只在控制层，不进入数据依赖排序。每条 E 指定唯一源 value 端口和目标具名端口。

运行证书检查：

1. 节点与边 id 唯一、端点存在、数据端口合法。
2. 输入无入边、输出无出边，同一目标端口恰有至多一个来源。
3. 数据边构成 DAG，可以拓扑排序。
4. 父级必须为智能体且严格高于子级；平台 3、协调 2、工作 1、其他原子 0。因此 H 无环。
5. 唯一输入 s 与唯一输出 t。
6. 所有执行节点都属于 `Reach(s) ∩ CoReach(t)`。

Kahn 排序与正反向可达遍历为线性复杂度（排序初始化另有排序开销）。`closed=true` 表示结构路径覆盖。它证明不存在游离的可执行模块或无终点支路，不证明函数终止、不证明输入类型相容、不证明工具存在，也不证明模型输出正确。工具和类型的合法性在调用时另行验证。

本版没有图上的条件路由端口；条件在函数节点内表达，因此证书不会声称覆盖模型任意返回标签。未来引入显式分支节点时，必须增加输出标签完备覆盖与分支排他性规则。

## 6. 并行、失败与记忆

调度器只启动所有数据依赖已成功的节点，独立节点最多四路并行。具名端口对应记录字段，不依赖边在 JSON 中的排列。输出节点恰执行一次。

失败使后继 skipped，互不依赖支路仍可完成，整次运行最终 failed。取消停止新调度，并丢弃尚未完成操作的迟到结果；底层 HTTP 只能在返回/超时处协作取消。

项目记忆由 SQLite 提供。有副作用的工具可改变外部状态；任务不是跨所有工具的分布式事务。已完成写入不因后续失败自动撤销。重放事件仅恢复观察记录，不会重新执行工具。本版无“exactly once 外部副作用”承诺，也无自动补偿、幂等键或失败自动重试。

## 7. 平台自调整与快照一致性

拓扑修改为 `(baseVersion, actor, reason, operations)`。后端在一个 SQLite 事务内完成读版本、作用域验证、应用补丁、全图验证、版本递增和变更事件写入；任何错误回滚。

平台必须显式有 graph.patch 能力，只能修改其后代。删除节点的隐式删边也检查全部端点作用域。新增节点必须归属当前平台，不能新增平台或授予 graph.patch；现有节点的身份、层级、工具配置不能被平台补丁更改。用户本人可在编辑器中更改配置。

运行前 `ensure-review` 策略检查输出前是否有复核，必要时自动补齐。`model-plan` 让模型在只读图能力下输出修改提案，然后由确定性校验器提交。模型结论无权修改校验规则。

开始运行时固化项目版本和完整图快照。运行期间图可以继续编辑，但不会让运行混用新旧版本。SSE 把已提交事件送到界面；图修订与运行版本分别标示。

## 8. 当前语言与表示范围

模块、控制流、data、异常处理、finally 清理与统一 IR 已在语言核心 v1 实现，见[当前范围](LANGUAGE_ROADMAP.md)。源文本、结构编辑与工作流投影编辑同一份规范程序；源码与图形投影共用语言语义；显式 executable 模式另记录真实镜像身份与授权项目快照，不能把镜像冒认成项目源码。导出、依赖和全部提供文件在任何顶层效果前统一检查。`finally` 是上下文关键字，不加入全局保留名称；IR 增加 `finally(body, cleanup)`，body 为块或原 try 节点，cleanup 为块，既有 try 字段不变。

普通可处理异常由 try/catch 接收；finally 为正常值、普通异常和语言控制信号提供清理。资源限制和已交付的取消不可被 catch 吞掉，也不执行 finally。显式 CancelShield 可在局部取消交付前完成其内部 finally；运行级硬控制和预算不被延迟，见[取消保护](CANCELLATION.md)。跨图节点的资源控制失败也不能转化为可捕获的普通业务错误。返回、break 与 continue 是控制信号。

没有注解的参数与返回值契约为 Any。data 契约只检查模块与类型身份、标签和参数数量，实例仍是可由普通记录构造的协议值。宏展开属于受限的纯编译阶段；生成器和语言级 async/await 使用同一挂起、任务与效果运行时。普通 fn、async fn、fn* 与 async fn* 的本体均可显式选择 [auto-flow／native-flow](NATIVE_FLOW.md) 的便携／LLVM 控制 CFG，动态调用、等待、生成器发送／委托与资源协议仍沿原语言语义执行；Task 和流保持冷构造，由调用者显式等待或消费。具体生命周期见 [挂起与任务](EFFECTS.md)，卫生与阶段限制见 [宏](MACROS.md)。完整静态类型推导、通用 AOT／跨目标 ABI 与自举尚未完成。

## 9. 嵌入与扩展边界

`Registry` 在 Framework 创建时生成快照。自定义工具通过 `ToolSpec` 声明输入输出契约和效果，自定义提供方每步接收 `AgentRequest`，返回 `ToolCall` 或 `Final`。运行时执行工具并把证据送入下一步历史；提供方不能通过返回动作绕过声明能力。宿主 Python 回调受信任，效果标签由宿主负责，不是进程沙箱。

项目保存显式能力集合。智能体工具声明必须属于项目授权；函数节点工具必须属于项目授权。源程序、图执行、嵌入式 SDK 和 REST 启动共享 Engine；每次执行固化项目、输入与能力快照。边界使用有界 JSON 值复制，拒绝函数、循环、非有限数、无效 Unicode 和超过 14,000 bit 的整数，避免宿主回调原位修改语言值。

每个文件数据库至多一个活跃运行时持有锁；第二个实例不会把第一个仍在执行的任务误恢复为中断。关闭先阻止新操作，取消并等待执行与独立平台优化排空，再释放数据库。用户回调必须自行配合 checkpoint；超时关闭保留锁供重试。等待结果的超时不等于取消任务。

`chaos run`、`check`、`fmt`、`ir`、`repl` 均可脱离 HTTP 服务使用。`check` 只检查语法、封闭包和导出结构，不执行程序，也不承诺证明所有动态名称、类型或终止性。


## 10. 流与模块宏的组合边界

同步和异步生成器都是词法环境中的运行时句柄，yield 暂停并接收消费者发送的值。异常注入沿暂停点的语言处理器传播，取消仍属于不可捕获控制信号。异步消费本身是 Task，共享运行预算；同流重入拒绝，多个不同流的外部效果可以并发。

模块宏在效果执行前展开。公开宏、私有辅助宏以及调用者注入的语法分别保持来源，不能通过同名捕获改变调用目标。原始源码树保留 import/export 和宏调用，展开树只用于执行，因此可视化修改与无界面运行不用维护两套程序。宏扩展不增加语言的抽象计算能力，也不证明模型行为正确。

## 11. 对象身份与可调用组件

Class 以运行时对象身份建立名义类型；同名重新声明的类不是同一类型。C3 在类定义时线性化多继承并拒绝冲突。类、实例、绑定方法与 super 代理归属于创建它们的解释器，读、写、调用和契约检查遵守这一归属。成员定义时求值；实例覆写可变字段建立自己的单元，不隐式复制默认对象。

方法与可调用实例进入原有函数调用跳板，继续保留实参绑定、尾调用、返回契约、异步句柄与能力边界。类值、实例和函数闭包不扩展图灵完备性论证所需的基础构造，它们提供程序组织和复用能力。完整规则见[对象规范](OBJECTS.md)。

## 12. 装饰与属性访问

`@d1`、`@d2` 的表达式先在声明位置从上到下求值。构造原声明值 v 后，依次计算 `d2(v)` 和 `d1(result)`，全部成功才绑定声明名。装饰器可以替换值的类型，不保证保持原签名；原命名函数私有自递归仍指向原函数，原类中的自身类型仍指向原类，符合既有词法快照规则。

classmethod 与普通方法共享统一调用入口，只改变显式接收者。property 的实例读写是有外部效果可能的语言调用；类访问和安全预览不执行它。使用同一所有权、参数契约、预算与取消规则，不将宿主 Python 属性查找暴露给用户程序。内置描述符不是完整的 Python 元对象协议。

## 用户描述符协议的调度与发布

用户访问协议是名义实例类型 MRO 上的普通可调用成员。数据描述符判定只检查类型上是否声明 `__set__` 或 `__delete__`；检查本身不运行方法。实例读取优先有 getter 的数据描述符，再自身状态，再非数据 getter，最后普通成员。类读取使用 `(null, actualClass)`，super 读取跳过锚点并保持实际派生类身份。

命名通知使用完整自身成员的固定快照。成员填充完成后 owner 已可使用，通知依次执行；外层类名在通知与类装饰器成功之后才发布。失败不会撤销已发生的工具效果、描述符内部修改或经其它状态泄露的 owner 引用。后续 setattr 不自动执行命名通知。

协议执行通过同一可挂起解释器。setter、deleter、命名通知返回 Null；显式 async/生成器钩子不作为这些同步协议接受，但普通 fn 内的 Agent 效果可以在已有 Task 内挂起。getter 返回的 Task/流句柄由调用者显式等待或消费。协议绑定受预算和深度限制，不能无限宿主递归。安全预览和类型能力判定不执行协议。

## 运算协议与效果次序

运行时实例比较可执行用户方法。列表元素按下标、记录值按左侧记录的字段插入顺序递归比较，逐项计费并在确定结果后短路。模式匹配仍采用无效果的结构/身份语义；不会为了选择分支调用模型。显式 `__ne__` 候选均拒绝时，语言反转运行时相等结果；这是一项明确的 Chaos 规则。

双向候选只有返回内部 NotImplemented 单例才表示拒绝；伪造 JSON 记录不会触发回退。不可调用方法、类型错误、用户异常、资源耗尽与取消也不会被吞掉转为回退。所有协议通过同一当前 Task 的调用栈执行。详细顺序与严格类型边界见[运算协议](OPERATORS.md)。

## 迭代器状态与消费协议

用户迭代通过原始类 MRO 和描述符绑定调用方法，返回显式 done/value 状态记录；异常不会被当作耗尽。工厂返回同步或异步游标，推进操作保持语言的单线程 AST 与可挂起效果调度。迭代器的终态、忙锁与关闭尝试属于当前运行周期；JSON 描述不携带可恢复的计算状态。

同一个原始实例在同一周期、同一同步/异步模式下对应同一适配器，避免用多个包装绕过重入保护。正常退出清理已经登记的游标，控制信号与资源限制跳过用户清理代码并排空在途效果；此前的实例状态和工具效果不回滚。详细契约见[用户迭代器](ITERATORS.md)。

## 属性、条目与语言版本

旧 index/set_member 节点继续保留原含义；新 subscript/set_item 明确表示条目访问，slice 表示有三项可省略边界的键。旧节点规范源码用 `object.[key]` 表示，避免渲染为新方括号后误调用户协议。旧 IR 无标记时视作语言版本 1，当前源码默认版本 2；版本不是模型名字，也不改变能力授权。

持久项目在入口 IR 的 sourceVersions 中记录每个模块的语法版本，首次加载历史项目不会写回源码或数据库。只有编辑的文件升级；未改模块维持原语义。运行、模块宏、验证、结构编辑和 IDE 草稿使用同一映射。新解析的方括号节点及语义哈希可以改变；兼容承诺是历史节点的意义与可往返性，不是不同语言版本解析结果字节恒等。

## 资源作用域

with/async_with 把管理器的一次求值、协议进入、词法 body、协议退出组成同一动态范围；多项头部等价于逐项嵌套。先解析并保存退出方法，进入成功后才建立退出义务；body 的尾调用在退出之前完成。只有普通 LanguageError 可以由退出方法显式抑制。return、循环转移与 GeneratorClose 运行普通退出后继续传播；ResourceLimit/ExecutionControl 直接传播并跳过用户钩子，与 finally 的硬控制规则一致。它不提供任意外部效果的回滚或强制终止不合作宿主代码的能力。完整可执行例见[资源作用域](CONTEXTS.md)。

## 结构目标的原子绑定

新结构声明按 RHS 求值一次、整值契约验证、完整结构匹配、当前层名字冲突检查、一次提交的顺序执行。前四步失败都不发布任何目标名字，已执行外部效果不回滚。`var` 叶子各自持有 `Any` Cell；整值注解不约束后续各叶赋值。循环与推导的每项使用新环境，失配立即抛 `match_error`。构造器在同一绑定前环境中查找；原 `match` 仍以失配继续下一分支。参见[解构绑定](PATTERN_BINDINGS.md)。

## 已有状态的结构化提交

`assign_pattern` 按右侧一次求值、完整纯匹配、所有 Cell 解析与契约检查、最终控制检查、不可挂起写回的顺序执行。匹配用右侧完成后的环境解析构造器。提交期间没有 tick、调试回调或用户方法；同一解释器的 Task 无法观察部分目标组。右侧本身不受互斥保护，其效果不回滚。资源模式在成功 acquire 后、受保护主体内完成新绑定，失配经过普通退出协议。详见[解构赋值与资源](PATTERN_BINDINGS.md)。

## 参数模式的调用边界

`name as pattern` 不改变实参的求值顺序或效果权限。完成全部参数的既有绑定和整值类型检查后，以函数捕获环境解析所有构造器，在临时映射中匹配全部模式。成功后发布整值槽及全部只读叶子；失配抛 `match_error`，且不运行主体或创建冷句柄。默认值的模式在调用时检查，默认表达式仍只在定义时求值。宏内部身份与公开关键字标签分离；结构匹配不执行用户协议。参见[参数解构](PATTERN_BINDINGS.md#函数参数中的模式)。

## Plan 的依赖与并发边界（0.39）

`max_concurrency` 是 Plan 定义的一部分，取整数 1–128。默认值规范成旧定义并保留串行扫描次序；大于 1 时，就绪步骤按声明顺序进入原生 TaskGroup，任一直接依赖未完成的步骤不会进入。前驱完成即释放后继，结果按步骤 id 寻址，外部完成次序不保证一致。输入及每步结果必须经过既有 JSON 边界；所有绑定在第一步前预检。

并发上限覆盖直接步骤的整个调用／等待周期，不等于整个后代树的任务或线程上限。失败停止新入组，按 TaskGroup 的优先级收束自有任务；已有借用任务保留原生命周期，外部副作用不回滚。Goal 和 Process 仍使用各自的持久检查点，不持久化活动并发栈。单次技能录制继续拒绝重叠工具执行。见[计划指南](AGENT_MODES.md)。

## 位置专用调用边界

`/` 把此前的非剩余参数标记为 positional_only。该模式只消费位置实参，忽略作为绑定来源的同名关键字；这些关键字留给 varkw，或在最终剩余检查时报错。缺少必需的位置参数仍报 argument_error。默认值顺序跨越 `/`，共享参数验证器在默认表达式执行前检查声明顺序。直接函数调用完成全部整值契约及模式绑定后才进入主体或创建冷句柄；外层 Team／Session 等效果封装保留各自调度生命周期，不因此提前执行内部函数。参数求值效果不回滚。参见[调用示例](FUNCTION_COMPOSITION.md#位置专用参数)。

## 结构异常处理和动态错误上下文

try_cases 依次在每个候选独立取得的原错误容器副本上匹配模式，成功后发布独立绑定并计算严格 Bool 守卫。无匹配重抛原 LanguageError，匹配／守卫／处理器错误直接向外传播；ResourceLimit 与执行控制仍不被捕获。单个无守卫名称 catch 保持旧 try 节点。try_else 的保护子节点允许 try_cases。

rethrow 读取执行上下文的活动普通错误，保留其身份及首次定位；无活动错误时产生 rethrow_error。catch 选择／处理与待决错误的 finally 建立动态范围，同步调用、尾调用和 TaskGroup 的词法主体继承。独立 Task／生成器不继承创建者或恢复调用者的错误，各自保留跨挂起状态。资源出口仅收到错误记录不自动建立此范围；完整语法和与 Python 的区别见[异常规范](EXCEPTIONS.md)。

## 名义类字段模式

`p_class(name, fields, rest)` 先在绑定前的环境解析完整 Class 身份，再验证实例的 C3 链并投影有效存储字段。默认子集匹配，类数据默认值与实例覆盖遵循已有遮蔽规则；计算属性不参与。投影无用户效果，递归检查所属与能力限制，未通过完整模式不发布绑定。宽权限不可代理活值明确失败。该规则贯通所有模式位置，见[类字段模式](CLASS_PATTERNS.md)。

## 原生集合

原生 Set 贯通运行时、宏和所有编辑入口。纯键保持精确类型与无钩子比较；运行时用户键使用共享同步哈希／相等协议，带所有权与能力上限。普通集合相等与插入顺序无关，迭代顺序固定；协议集合在纯模式中按身份比较。构造与推导逐项执行、校验、去重，输入预算计入重复项。无效项阻止后续效果，先前效果不回滚。集合可经 Channel 传递合规成员；Set 成员递归纳入消息检查，Instance 成员在此验证自身所有权，其字段访问、调用与捕获仍沿既有 owner／epoch／能力检查。Function／Task 等仍不可直接作为集合键，严格 JSON 边界不变。碰撞比较、共享结构、数据投影与格式化规则见[集合规范](SETS.md)。


## 0.72.0：原生任务局部上下文

[任务局部上下文与动态绑定](DYNAMIC_CONTEXTS.md)说明 ContextVar、ContextToken、ContextScope 和 Context 的实际语言语义：普通任务/生成器创建时浅复制绑定，词法与透明协议调用共享上下文，选定 async 回调原 AST 执行，退出与取消恢复绑定。上下文可保存合法原生语言值，不能扩大工具权限。源码/IR、IDE、CLI、SDK 与 HTTP 共用实现；复制是有界 O(n)，宿主 GC 未被替换。本增量不表示完整 Python/Lisp 生态或自托管已经完成。

## 多返回值完成

[显式多返回值](MULTIPLE_VALUES.md)将零／单／多个结果放入原调用完成协议。普通操作数、绑定、实参、默认值、容器与协议取首项；零结果为 null。块、分支、return、管道调用、尾调用、资源与 finally 保留完整结果，返回注解检查首项。全部次项仍经过所有权、权限投影、捕获图和预算检查。显式 producer 回调负责捕获与连接，完成身份不会存入普通数据或 JSON；全局 values(obj) 继续提取 Record 值。

显式完成的本轮 Task／Generator／AsyncGenerator 也可作为多结果 producer，只读已经保存的完整终值。接收器不启动、等待、推进或重放句柄；未完成、失败、取消、关闭、外来或过期句柄沿生命周期与权限合同拒绝。

## 身份提示、动态出口与展开

[控制提示](CONTROL_PROMPTS.md)在原栈安装身份范围，向最近可访问目标转移零／单／多个完成结果。处理器在目标移除与内层清理后执行；非局部转移沿既有 with／finally／TaskGroup 控制路径展开，普通 catch 不拦截控制信号。真实子 Task／流控制状态独立，透明协议与词法组主体共享。Chaos 向外屏障限制外层目标，wind 回调保持预算、清理优先级和完整结果验证；动态 escape 本身不保存已经返回的计算；另有[同步组合式 continuation](CONTINUATIONS.md)显式保存支持的后缀，并在每次调用时重新执行该后缀，原前缀不重放。

## Robot 观察与命令准入

[原生 Robot](NATIVE_ROBOTS.md)观察保留单一包的原 receivedAtNs／sequence，命令绑定最新观察、租约、能力与共享消费位。宿主准入和适配器写字节前检查同一观察起算绝对期限；延迟 await 不重开 TTL。未知写入停止普通命令并退役，不能用重试或 JSON 重建权威。所有效果、资源清理与 async 流仍使用原解释器。


## 默认求值游标与待决执行状态

[执行帧](EXECUTION_FRAMES.md)把默认操作数及普通函数调用／返回阶段的待决状态放入原调度器所驱动的类型化游标。已求值操作数、实参顺序、返回合同、完整多结果、源位置和权限仍决定真实后续执行；词法 Cell／原生身份共享，临时帧完成或展开后释放。保护范围、迭代与模式分支等已迁移部分由相应真实帧推进；模块初始化与导入也由真实模块状态帧推进，解析、链接、宏展开和整个调度周期仍保留原同步准备与协调边界。此变化不复制用户堆、不重放前缀效果、不改变默认 AST 更新合同，该内部表示本身不授予任意活栈复制权；已登记同步解释段的保存／组合和新 wind 激活见[Continuation](CONTINUATIONS.md)，Task、编译段与线性资源仍有明确屏障。

`match` 及结构声明／赋值现在由同一真实模式帧保存待决值、分支位置、守卫、主体和词法范围。只求值一次的被匹配值、失败守卫的既有效果、严格 Bool、选中主体的尾位置与完整多结果仍保持原定义；结构赋值的原子性仅覆盖最终 Cell 提交，不回滚右值效果。纯模式算法在所有绑定位置继续共用，不执行用户协议。此内部状态迁移不增加可保存 continuation 或外语兼容声明，见[模式执行状态](EXECUTION_FRAMES.md#h-模式分支与结构绑定的执行状态)。

封闭模块初始化、普通同步模块加载、import／export 与 callable 导出入口也沿[真实模块状态帧](EXECUTION_FRAMES.md#模块初始化导入与导出入口的执行状态)执行。每实例缓存与失败清理保持原语义，普通加载不合并原逐语句 evaluate／resolve Runner；全图解析、卫生宏、源注册准备及原调度周期仍保留自己的边界。

## 编译保护范围

auto-flow／native-flow 的直接保护结构复用上述原语义：守卫后的真实后继、正常完成 else、尾调用解析与清理均保持原边界。清理中内层循环已经消费的局部转移不抹去外层待决控制；新普通清理错误按原规则覆盖旧普通完成。编译不扩大 catch 可处理的硬错误，不把原生 GeneratorExit 与 GeneratorClose 合并，也不新增借用资源的清理义务。未直接选中的宿主子树仍沿原语义事件执行。这是当前支持的编译范围；实际版本的测试、分发与安装仍分别验收。
