# 编译与运行时设计

本页描述当前实现与扩展约束。Chaos 用同一语言 AST、词法环境、执行帧和效果运行时连接解释、编译与 Agent／Bot／Robot 组合；不以完整 Python／Lisp 兼容、通用 AOT 或独立 GC 作为当前语言可用的前提。对外组合合同见[语言核心合同](LANGUAGE_CONTRACT.md)。

## 一条语义管线

源码由原解析器构成 AST，经作用域／模块检查和受限纯宏展开，再进入原求值器。默认执行使用真实类型化帧保存待决阶段、作用域、操作数和错误；Task／流由原调度器推进。动态调用、用户协议、权限、预算和资源退出都使用这套实现，编译后端不能另造一套有不同效果顺序的解释器。

函数形成时处理默认值与名称快照；已有 Cell 共享。完整完成协议区分零结果、单个 null、一个 List 与多个结果。tail、多结果投影及标量区域资格分别传递，不能因 CFG 的某条边合并这些语义选项。

## 编译产物与运行入口

| 形式 | 保存什么 | 加载与执行 |
| --- | --- | --- |
| 静态编译报告 | 模块／依赖身份、保守潜在效果与分析信息 | `program_compile`／`Framework.compile`／`chaos compile` 不执行程序，报告不能当运行输入 |
| 源码型 artifact | 源码包和可验证的便携 Flow 模板 | 加载重新解析、展开和降低，并比较模板；实际执行仍走原运行时，见[编译指南](COMPILER.md) |
| executable 镜像 | 已展开的封闭 AST、导入／导出、精确数值、卫生和受限构造器数据 | `load_executable` 解码、全图验证并建立源代码无关的静态优化计划；不调用 Parser／宏展开；显式 JIT 仍可降低 AST |
| 本机对象缓存 | 原可信生成器发射的机器对象和认证元数据 | 匹配目标的可信进程先认证再重链接；不保存活状态或提供语言／HTTP 任意二进制加载 |

可执行 AST 是 executable 的唯一程序语义，不并列保存可独立篡改的第二份 CFG。装载在初始化任何模块前验证整个闭包，包括孤立单位、结构角色、控制上下文、路径、导入／导出、依赖及标准库身份。哈希标识内容，不证明来源可信或与某份源码等价；修改后合法的 IR 是另一份程序。

持久 `start_executable` 使用原 Engine、RunHandle、Context、事件、指导、取消和资源管线。运行快照分别记录不可变镜像及授权项目版本；镜像不伪造缺失源码、源码调试位置或 `current_program`。显式 source Program 子调用使用自己的来源，见[SDK](SDK.md)。

## 独立库、宏接口与命名空间

`compile_objects(..., libraries=None)` 保留 v1 封闭源码编译。显式 `libraries=[]` 或对象列表启用 v2：只解析／展开客户端源码，库提供已验证的运行时树。v2 每个模块记录自己的标准库传递闭包和直接依赖对象内容身份。旧 v1 先完整验证再升级元数据，不重新解析库树。

`macro_interfaces=True` 显式发布 v3；客户端收到 v3 库时也采用 v3，并保留本地宏接口。受验证的 `chaos.macro-phase/1` 胶囊保存原始宏声明 AST、私有帮助宏及定义处导入所需信息。客户端调用沿原 Expander、纯内建环境、卫生规则和共享预算执行。它不保存 Env、Function、宿主回调或权限；链接／加载不运行宏。合法但纯解释器不支持的未调用宏体保持延迟拒绝，实际调用才报错。旧 v1／v2 缺失宏实现时不猜测或伪造源码。

依赖按精确实现内容绑定；替换库后须重编依赖它的客户端。动态导出成员仍由运行时检查，这不是静态类型链接或稳定可替换的符号 ABI。

`mount_objects(objects,prefix)` 先完整准入闭包，再统一重定位非标准模块、导入目标、精确依赖和登记的运行时／阶段元数据，拓扑重算内容身份并全量复验。普通字符串、数值和卫生参数别名保持数据；`sourceHash` 保留原始来源指纹。源码位置参与 import 解析和 data 类型身份，不能当作无关注释丢弃。无法可靠重定位的来源明确拒绝；标准模块保持规范化后的原对象，反向依赖或指向非标准模块的来源无法保持时拒绝。挂载不解析／展开／执行库，也不改变原 flat libraries 的冲突规则。

## 真实控制流与语义帧

`auto-flow`／`native-flow` 覆盖普通、async、generator 和 async generator 函数。LLVM 或 portable 后端从真实 PC 选择结构后继，宿主执行原帧、Env／Cell、类型和效果协议。结构分支、循环、保护、资源和模式有明确事件；未选择的子树保留宿主 AST 语义，不宣称全机器码。

call、let、var、list、tuple、record、binary、unary 和 do 的子表达式递归降低，原 OperandFrame 继续决定阶段、短路、参数展开、契约和完整结果。名称赋值、成员／索引读写及复合赋值的子表达式由原 ClassSyntaxEvaluationFrame／ObjectAccessEvaluationFrame 推进；原 ItemKeyFrame 处理标量、slice 非空端点及多索引键。对象、键、旧值、右值依原顺序求值一次；合法提交前的失败保留已发生效果，不伪造回滚。

当前 await／yield／yield from 与 throw／重抛保留原挂起语法和宿主协议边界；不能把未采用的进一步 lowering 当作已发布覆盖。实际支持以当前 `jit_flow` 和对应专题为准。详见[原生控制流](NATIVE_FLOW.md)与[执行帧](EXECUTION_FRAMES.md)。

运行期间在既有结构／叶子检查点检查定义稳定性。失效保留已经提交的前缀并按原错误优先级展开，不重跑调用或已发生动作；跟踪／调试从当前 PC 切换 portable，不从头执行。区域守卫失败只回退当前区域，不能重新授予父路径已禁用的区域资格。

## 数值特化、效果与性能

标量／区域 LLVM 后端针对可证明的整数运算，范围守卫保留任意精度语言语义。常量折叠、公共子表达式消除和区域 DAG 调度只改变已证明的纯数据计算，完整逻辑检查点和源位置仍按原顺序执行。包级字面量／不可变词法整数特化也不省略原名称读取、协议或检查点。详见[标量优化](SCALAR_OPTIMIZER.md)。

静态效果分析是保守的潜在效果，不是跨过程纯度证明。未知调用、用户协议、状态、挂起、模块初始化和外部效果不能因名字相似而被删除或重排。导出未引用不证明模块初始化无效果；当前不做整程序死代码删除或 LLVM ThinLTO。

物理代码缓存强保仍被函数引用的引擎和对象资源，clear／evict 不破坏活包装函数。显式私有 NativeObjectCache 绑定完整生成 IR、符号／调用 ABI、codegen、LLVM／llvmlite、目标／布局／宿主条件；对象和元数据整体认证先于链接，默认不启用磁盘存储。缓存不包含当前 Env、回调地址、语义栈、权限或工具结果。详见[原生函数](NATIVE_FUNCTIONS.md)及[SDK](SDK.md)。

不能用减少 IR 指令、增加帧数或缓存命中次数推导提速。冷／热编译耗时、执行耗时、尾延迟和内存必须在指定平台实测。小函数可能因守卫和检查点更慢。

## 根域、终态退役与内存

内部 `rooted-host-events/2` 将 ABI、调用域、事件类型、位置、代际 token 和下一 PC 一起验证，再解析实际事件载荷进入原帧。函数、作用域、结果和待决引用使用本次域中的真实槽作为存储；native／portable 共享解析，不以影子表监测代替实际派发。外域、过期、已关闭或错误 owner／epoch 在效果前拒绝，finish 只退役本次拥有的域。

已证明完全排空的终态 Task／流释放已消费输入、执行上下文和闭合游标的运输根，保留原闭合空游标身份、结果、完整多值、错误和必要调度元数据。未知或仍活跃的 native／辅助游标保守保留，验证全图通过后才释放；借用模块协调账本和外部句柄不因退役被关闭。返回值、共享 Cell、异常及其 traceback 仍可保有对象。

对象堆仍由 Python 宿主管理；根槽、预算和消费根退役不等于独立 GC、全语言堆配额或 RSS 限制。`std/memory` 是持久键值／CAS，不是堆回收器。资源退出仍由 with／ExitStack／TaskGroup 等显式合同负责，不能依赖回收时机。

## 控制与外部资源

同步[组合式 continuation](CONTINUATIONS.md)已经支持登记的解释后缀、多次调用、共享既有 Cell 和 fresh wind 激活。它不是机器栈复制或整个堆快照。活动 Task／流、编译 FlowState、资源、TaskGroup、Mode lease／录制和未知 native 仍是屏障；编译帧和根域不会自动增加捕获或复制权。

Agent、Bot 和 Robot 在同一函数／效果模型中组合。新后缀中的效果每次调用仍需实际准入，前缀不重放不等于全局恰好一次。Goal／Process、版本事务和不确定结果协调继续管理长期工作；串口 sent 或软件夹具通过不证明硬件达成。

## 可选技术方向与验收

通用机器码 AOT、全语言对象布局／独立 GC、跨目标运行时 ABI、通用异步 continuation、热点后台编译和更广 GPU 后端都需要独立设计及证据；它们不是 Python／Lisp 对齐清单，也不是本页的交付承诺。当前 llvmlite 后端使用 MCJIT，不是 ORC；GPU 已有受限 Float32 Task、Tensor 适配和结构 Metal 生成，不是通用 GPU 语言。

扩展必须比较真实值、错误类型／位置、完整多返回值、求值及效果次序、预算阈值、取消和清理；还要证明权限、借用、定义稳定性、公共入口和分发一致。模型只提出候选，不能豁免验证。性能、设备与来源信任分别验收，有限测试不能证明任意程序终止或全部优化正确。
